## 2. 测试目标

### 2.1 总体目标

确保"易购"电商平台 v2.4.0 版本的各项功能符合需求规格说明，系统性能满足设计指标，用户体验流畅，为正式上线提供质量保障。

### 2.2 具体目标

| 目标编号 | 目标描述 | 衡量标准 |
|----------|----------|----------|
| OBJ-001 | 功能完整性 | 需求覆盖率达到 100%，功能测试用例执行率 100% |
| OBJ-002 | 缺陷密度 | 严重及以上级别缺陷遗留数为 0，一般缺陷遗留数 ≤ 5 |
| OBJ-003 | 系统性能 | 核心接口响应时间 P95 < 2s，系统可用性 > 99.9% |
| OBJ-004 | 兼容性 | 通过主流浏览器和设备的兼容性测试 |
| OBJ-005 | 安全性 | 通过第三方安全扫描，无高危及以上漏洞 |

## 3. 测试范围

### 3.1 测试范围

本测试计划涵盖"易购"电商平台的核心功能模块：

| 模块 | 测试内容 | 优先级 |
|------|----------|--------|
| 用户管理模块 | 注册、登录、个人信息管理、权限控制 | P0 |
| 商品管理模块 | 商品展示、搜索、分类、详情 | P0 |
| 订单管理模块 | 购物车、下单、订单状态流转、订单查询 | P0 |
| 支付模块 | 支付接口、退款处理、支付安全 | P0 |
| 库存模块 | 库存扣减、库存同步、库存预警 | P1 |
| 营销模块 | 优惠券、满减活动、积分系统 | P1 |
| 后台管理模块 | 商品上架、订单处理、数据统计 | P1 |
| 消息通知模块 | 短信、站内信、推送通知 | P2 |

### 3.2 不包含范围

以下功能或场景不在本次测试范围内：

| 项目 | 说明 | 原因 |
|------|------|------|
| 第三方物流系统对接 | 物流轨迹查询、电子面单 | 由第三方提供独立测试报告 |
| 移动端 APP 专项测试 | iOS/Android 原生应用 | APP 独立版本计划 |
| 历史数据迁移 | v1.x 到 v2.x 数据迁移 | 由运维团队单独负责 |

## 7. 测试策略

### 7.1 功能测试策略

| 策略 | 说明 | 应用范围 |
|------|------|----------|
| 黑盒测试 | 基于需求文档设计测试用例，验证功能正确性 | 全部功能模块 |
| 等价类划分 | 对输入数据进行有效/无效等价类划分 | 表单输入、参数校验 |
| 边界值分析 | 重点测试边界条件 | 价格、数量、长度限制 |
| 场景法 | 设计用户真实使用场景进行端到端测试 | 购物流程全流程 |
| 错误推测 | 基于经验推测可能的错误点 | 异常流程、异常输入 |
| 探索式测试 | 测试人员自主探索潜在问题 | 第一轮测试后期 |

### 7.2 接口测试策略

| 测试类型 | 测试内容 | 覆盖率目标 |
|----------|----------|------------|
| 正向测试 | 正常参数调用，验证返回结果正确 | 100% |
| 反向测试 | 异常参数调用，验证错误处理 | 100% |
| 参数校验 | 必填项、数据类型、长度限制、格式校验 | 100% |
| 鉴权测试 | Token 有效性、权限控制、过期处理 | 100% |
| 并发测试 | 多线程同时调用，验证数据一致性 | 核心接口 |
| 异常测试 | 超时、服务降级、熔断场景 | 关键接口 |

### 7.3 性能测试策略

| 测试类型 | 测试目标 | 指标 |
|----------|----------|------|
| 负载测试 | 逐步增加并发用户数，确定系统最大承载能力 | 找到拐点 |
| 压力测试 | 超过设计容量运行，验证系统稳定性与恢复能力 | 错误率 < 1% |
| 并发测试 | 模拟秒杀场景，验证库存扣减准确性 | 无超卖 |
| 稳定性测试 | 7×24 小时持续运行，检测内存泄漏等问题 | 无异常重启 |
| 容量测试 | 验证系统在不同数据量级下的性能表现 | 响应时间达标 |

## 8. 缺陷管理

### 8.1 缺陷严重程度定义

| 级别 | 定义 | 处理时限 | 示例 |
|------|------|----------|------|
| 致命 (Critical) | 系统崩溃、数据丢失、安全漏洞 | 4小时内 | 支付金额计算错误、数据库死锁 |
| 严重 (Major) | 核心功能不可用、主要流程阻断 | 24小时内 | 无法下单、无法支付 |
| 一般 (Minor) | 次要功能异常、有替代方案 | 3天内 | 页面样式错乱、提示信息错误 |
| 轻微 (Trivial) | UI 问题、建议性改进 | 下个版本 | 文字拼写错误、布局微调 |

### 8.2 缺陷优先级定义

| 优先级 | 说明 | 处理顺序 |
|--------|------|----------|
| P0 (紧急) | 阻塞测试进度，必须立即解决 | 第1优先级 |
| P1 (高) | 严重影响功能，需要尽快解决 | 第2优先级 |
| P2 (中) | 影响有限，按计划解决 | 第3优先级 |
| P3 (低) | 可延期处理 | 第4优先级 |

### 8.3 缺陷状态流转

```
新建 (New)
   │
   ▼
指派 (Assigned) ←──── 重新打开 (Reopened)
   │                       ▲
```

|------|------|

| 数据克隆 | 复制已有数据进行修改 | 相似场景数据 |

### 11.3 敏感数据处理

- 所有手机号使用测试号段（如 13800000000 ~ 13800000999）
- 身份证号使用测试专用号码
- 银行卡号使用测试卡号
- 真实姓名使用虚拟姓名

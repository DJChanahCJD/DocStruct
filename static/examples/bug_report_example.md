## 4. 问题摘要

### 4.1 现象描述

登录用户在商品详情页点击"加入购物车"按钮后，页面弹出"操作失败，请稍后重试"错误提示，商品未能成功加入购物车。浏览器开发者工具显示 `/api/cart/add` 接口返回 HTTP 500 错误。

### 4.2 影响范围评估

| 评估项 | 影响程度 | 说明 |
|--------|----------|------|
| 用户影响 | 🔴 **高** | 影响所有通过详情页购买商品的用户 |
| 业务影响 | 🔴 **高** | 直接导致商品无法正常购买，影响转化率 |
| 数据影响 | 🟢 **无** | 未产生脏数据或数据丢失 |
| 安全影响 | 🟢 **无** | 不涉及安全漏洞 |
| 性能影响 | 🟢 **无** | 不涉及性能问题 |

**影响面估算**：约 60% 的购物车操作通过详情页完成，该缺陷阻断核心购买流程。

## 6. 根因分析

### 6.1 初步分析

通过查看后端日志和代码审查，定位问题原因：

**问题代码位置**：`cart-service/src/main/java/com/mall/cart/service/impl/CartServiceImpl.java:187`

**问题描述**：
```java
// 问题代码
SkuInventorySnapshot snapshot = skuService.getInventorySnapshot(skuId);
int availableStock = snapshot.getAvailableStock();  // ← NullPointerException
```

当商品的某个规格 SKU 没有库存快照记录时，`getInventorySnapshot()` 返回 `null`，后续调用 `getAvailableStock()` 导致空指针异常。

### 6.2 根本原因

1. **数据层面**：部分历史 SKU 数据缺少库存快照记录
2. **代码层面**：未对库存快照为空的情况进行防御性编程
3. **测试层面**：测试数据准备时未覆盖"SKU 无库存快照"场景

### 6.3 代码流程图

```
用户点击"加入购物车"
        ↓
调用 /api/cart/add 接口
        ↓
参数校验（通过）
        ↓
查询 SKU 基本信息（通过）
        ↓
查询 SKU 库存快照 ← 返回 null（问题点）
        ↓
获取可用库存 ← NullPointerException
        ↓
返回 500 错误
```

## 8. 修复方案

### 8.1 修复内容

**文件**：`CartServiceImpl.java`

**修改内容**：
```java
// 修复后代码
SkuInventorySnapshot snapshot = skuService.getInventorySnapshot(skuId);

// 添加空值检查
if (snapshot == null) {
    log.warn("SKU {} 缺少库存快照记录，视为无库存", skuId);
    throw new BusinessException(ErrorCode.SKU_STOCK_NOT_FOUND, "商品库存信息不存在");
}

int availableStock = snapshot.getAvailableStock();
```

### 8.2 补充措施

1. **日志增强**：在异常处理中增加更详细的上下文日志，便于问题定位
2. **监控告警**：增加"SKU 库存快照缺失"监控指标
3. **数据修复**：批量检查并补全缺失库存快照的 SKU 数据

## 13. 经验总结

### 13.1 问题反思

1. **防御性编程不足**：对外部服务返回的数据未进行充分的空值检查
2. **测试覆盖不足**：测试数据准备时未考虑"库存快照缺失"的边界场景
3. **监控缺失**：缺乏对关键数据完整性的监控告警

### 13.2 预防措施

1. 在代码审查 Checklist 中增加"空值检查"项
2. 完善测试数据准备规范，覆盖更多边界场景
3. 建立数据完整性监控机制，及时发现缺失数据

# 智能文档系统概要设计

## 文档信息

| 项目 | 内容 |
|------|------|
| 文档版本 | v1.0 |
| 文档类型 | design |

## 1. 系统架构

系统采用前后端分离架构，由 Web 前端、API 服务、文档解析服务和数据库组成。

| 模块 | 职责 |
|------|------|
| Web 前端 | 提供文档上传、查看和搜索界面 |
| API 服务 | 处理认证、文档管理和检索请求 |
| 文档解析服务 | 将 PDF、Word、Markdown 转换为结构化文档 IR |
| 数据库 | 存储文档记录、解析结果和抽取结果 |

## 2. 核心流程

### 2.1 文档处理流程

1. 用户在 Web 前端上传文档。
2. API 服务保存原始文件并创建文档记录。
3. 文档解析服务生成文档 IR。
4. 抽取模块根据文档类型输出结构化对象。
5. API 服务更新处理状态并返回结果。

## 3. 接口设计

| 接口 | 方法 | 路径 | 目标模块 |
|------|------|------|----------|
| 上传文档 | POST | /documents | API 服务 |
| 查询文档 | GET | /documents/{document_id} | API 服务 |
| 解析文档 | RPC | ParseDocument | 文档解析服务 |

## 4. 设计决策

- 文档 IR 使用稳定元素 ID 支持证据回溯。
- 抽取结果统一映射到实体、流程、需求、接口和产物五类对象。
- 解析失败时保留错误信息，避免覆盖原始文档记录。
